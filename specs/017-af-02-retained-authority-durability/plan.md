# AF-02 + Dependency Security Dual-Bootstrap Repair Plan

Status: DUAL_BOOTSTRAP_REPAIR_CANDIDATE
Issues: #100, #99
Entry main: `18819c7fdaee618f4aa86c6c3279b1acb70ec9f2`

## Why one bootstrap PR is required

The defects remain independently owned:

- #100 repairs AF-02 retained-authority durability after the historical Actions artifact aged out of GitHub retention;
- #99 removes `RUSTSEC-2026-0285` by moving the resolved `rustls` dependency from `0.23.43` to patched `0.23.45`.

They are combined only because the active `commandF main assurance` ruleset requires `rust`, `assurance-proof`, and `scorecard` with strict required-status-check policy and no bypass actors.

The AF-02 repair by itself proves `rust` but cannot satisfy `assurance-proof` while #99 remains. A #99-only PR against current main would still inherit the AF-02 `rust` failure. Neither repair can become canonical first without weakening or bypassing a required gate. The dual-bootstrap PR resolves that cycle while retaining separate commits, issue ownership, acceptance evidence, and closure semantics.
